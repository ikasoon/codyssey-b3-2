# 한국어 Git 커밋과 PR 초안 생성기

현재 저장소의 변경을 읽어 한국어 변경 요약, 커밋 메시지 또는 PR 제목·본문을 생성하는 CLI다. OpenRouter를 기본으로 사용하고 Pydantic AI를 통해 다른 LLM 제공자로 전환할 수 있다. 생성 결과는 [수동 검토 절차](#수동-검토-절차)를 거쳐 복사해 사용한다.

## 설치

Git, [uv](https://docs.astral.sh/uv/getting-started/installation/), [just](https://just.systems/man/en/packages.html)를 설치한 뒤 저장소 루트에서 실행한다.

```sh
just setup
just test
```

uv가 `.python-version`에 지정한 Python 3.12와 `uv.lock`의 의존성으로 `.venv`를 구성한다. Python 3.10 이상을 지원하며 별도의 가상환경 활성화는 필요 없다. Pydantic AI는 필요한 제공자만 포함하는 `pydantic-ai-slim[openrouter,openai,anthropic]` 배포판을 사용한다.

## API 키와 모델 설정

루트 `.env`에 다음 항목을 설정한다. 기존 파일이 없으면 `.env.example`을 복사해서 시작할 수 있다.

```dotenv
OPENROUTER_API_KEY=발급받은_OpenRouter_API_키
LLM_MODEL=openai/gpt-4.1-mini
```

변수 이름은 대문자 `OPENROUTER_API_KEY`다. `.env`는 애플리케이션 시작 시 읽으며, 이미 설정된 셸 환경변수가 우선한다. 키는 코드나 CLI 인자로 입력하지 않는다. `.env`는 Git 제외 대상이다.

모델에는 코드 기본값이 없다. 위 모델 ID는 설정 예시이며, 사용할 모델을 `.env`·셸 환경변수의 `LLM_MODEL` 또는 `--model`로 반드시 지정한다. 초안 생성 시 모델이 없거나 공백뿐이면 API 호출 없이 오류로 종료한다.

## 실행

```sh
just commit
just pr
just commit --model openai/gpt-4.1-mini --temperature 0.2 --max-tokens 2048
just pr --safe-mode
```

같은 명령을 Python 진입점으로도 실행할 수 있다.

```sh
just run python main.py commit
uv run --locked python main.py pr
just commit --help
```

반드시 Git 저장소 루트에서 실행한다. 스테이징된 변경, 아직 스테이징하지 않은 변경, Git이 무시하지 않는 새 파일을 함께 수집한다. `git status`와 `git diff`만 사용하며 새 파일은 `git diff --no-index`로 읽는다. 인덱스와 작업 파일은 수정하지 않는다. 병합 충돌이 있으면 먼저 해결해야 한다.

변경이 없거나 제외 후 요약할 diff가 없으면 API 호출 없이 종료한다. 성공·변경 없음은 종료 코드 `0`, 설정·Git·API·출력 검증 오류는 `1`, 잘못된 CLI 인자는 `2`, 사용자 중단은 `130`이다. 초안은 표준 출력, 상태·오류·호출 횟수는 표준 오류로 출력한다.

| 옵션 | 기본값과 의미 |
| --- | --- |
| `--provider` | `openrouter`; 제공자 선택 |
| `--model` | 기본값 없음; 모든 제공자에서 `--model` 또는 `LLM_MODEL` 필수 |
| `--temperature` | `0.2`; 이 CLI의 허용 범위는 `0`~`1` |
| `--max-tokens` | `2048`; 응답 토큰 상한 |
| `--api-timeout` | `60`; API SDK 타임아웃(초) |
| `--git-timeout` | `30`; Git 명령당 타임아웃(초) |
| `--base-url` | OpenAI 호환 제공자의 API 주소 |
| `--api-key-env` | 키가 들어 있는 환경변수 **이름** |
| `--safe-mode` | 기본 활성화; 입력량 제한 |
| `--no-safe-mode` | 입력량 제한 해제 |

옵션은 `commit`·`pr` 앞이나 뒤에 사용할 수 있다. 과제 예시의 `-model`, `-temperature`, `-max-tokens`, `-safe-mode` 표기도 지원한다.

## 설정 관리와 우선순위

`gitdraft/config.py`의 `Settings`가 실행 설정의 기본값과 타입·범위를 정의한다. 저장소 루트 `.env`를 한 번 읽고 기존 셸 환경변수를 유지한 뒤, [Pydantic Settings](https://docs.pydantic.dev/latest/concepts/pydantic_settings/)로 검증한다. 우선순위는 **명시한 CLI 옵션 > 셸 환경변수 > .env > Settings 기본값**이다. CLI에서 생략한 옵션은 환경 설정을 덮어쓰지 않으며 `temperature=0`, `safe_mode=false`도 그대로 적용한다.

| CLI 옵션 | 환경변수 | 기본값·조건 |
| --- | --- | --- |
| `--provider` | `LLM_PROVIDER` | `openrouter` |
| `--model` | `LLM_MODEL` | 기본 모델 없음; 생성 시 필수 |
| `--temperature` | `LLM_TEMPERATURE` | `0.2`; 유한한 수, `0`~`1` |
| `--max-tokens` | `LLM_MAX_TOKENS` | `2048`; 양의 정수 |
| `--api-timeout` | `LLM_TIMEOUT_SECONDS` | `60`; API SDK 타임아웃, 양의 유한한 초 단위 수 |
| `--git-timeout` | `GITDRAFT_GIT_TIMEOUT_SECONDS` | `30`; Git 명령당 제한 시간, 양의 유한한 초 단위 수 |
| `--safe-mode` / `--no-safe-mode` | `GITDRAFT_SAFE_MODE` | `true`; `.env`에는 `true` 또는 `false` 권장 |
| `--base-url` | `LLM_BASE_URL` | OpenAI 호환 제공자에서 필수 |
| `--api-key-env` | `LLM_API_KEY_ENV` | 선택한 제공자의 기본 키 변수 이름 |

아래 항목을 기존 `.env`에 추가하면 반복 입력을 줄일 수 있다. API 키는 기존 제공자별 키 변수를 그대로 사용한다.

```dotenv
LLM_TEMPERATURE=0.2
LLM_MAX_TOKENS=2048
LLM_TIMEOUT_SECONDS=60
GITDRAFT_GIT_TIMEOUT_SECONDS=30
GITDRAFT_SAFE_MODE=true
```

키 값과 모델에는 대체 기본값이 없다. 알려진 설정의 빈 값·타입 오류·범위 초과는 기본값으로 대체하지 않고 오류로 처리한다. 변경이 없어 초안을 생성하지 않을 때는 모델·API 키 없이도 정상 종료한다. API 키와 잘못된 설정값 원문은 오류 메시지에 포함하지 않는다.

입력 제한, 자동 재시도 0회, 모델 요청 최대 1회와 제목 길이는 `gitdraft/policy.py`의 고정 규칙이다. 환경변수로 변경하지 않으며 안전 모드 해제 시에도 민감 파일 제외와 마스킹은 유지한다. TOML 설정 파일은 사용하지 않는다.

## 생성 파라미터 조정

### temperature와 무작위성

`temperature`는 다음 토큰을 고르는 확률 분포에 영향을 준다. 낮추면 가능성이 높은 표현에 집중하고, 높이면 덜 흔한 표현도 선택해 결과의 다양성과 창의성이 커진다. 사실 정확도를 직접 조절하는 값은 아니며, 낮게 설정해도 잘못된 추론이 사라지거나 매번 같은 결과가 보장되지는 않는다. [OpenRouter 샘플링 파라미터 설명](https://openrouter.ai/docs/api_reference/parameters#temperature)을 참고한다.

이 프로젝트는 변경 사실과 정해진 본문 형식을 전달하는 용도이므로 기본값 `0.2`에서 시작한다. 아래 범위는 실측 최적값이 아닌 조정 출발점이다.

| 설정 범위 | 기대하는 효과와 사용 기준 |
| --- | --- |
| `0`~`0.2` | 표현의 변동을 줄이고 반복 가능한 요약을 우선할 때 사용한다. |
| `0.3`~`0.5` | 같은 변경을 설명하는 다른 표현을 검토할 때 시도한다. |
| `0.6`~`1` | 표현의 다양성이 커질 수 있으나 근거 없는 설명과 형식 이탈 여부를 더 꼼꼼히 검토한다. |

다른 설정과 함께 볼 때는 다음을 구분한다.

- **`max_tokens`**: 온도는 토큰 선택, 토큰 상한은 생성량을 제어한다. 온도를 낮춰도 작은 출력 예산으로 잘리는 문제는 해결되지 않으며, 상한을 늘려도 내용의 정확성이 보장되지는 않는다.
- **`top_p`**: 누적 확률에 따라 후보 토큰 범위를 제한하므로 온도와 함께 결과의 다양성에 영향을 준다. 둘을 동시에 바꾸면 원인을 비교하기 어렵다. 현재 CLI는 `top_p`를 노출하거나 명시적으로 전달하지 않으므로 제공자 기본 설정을 유지하고 온도부터 조정한다. [OpenRouter의 `top_p` 설명](https://openrouter.ai/docs/api_reference/parameters#top-p)을 참고한다.
- **모델과 프롬프트**: 같은 온도라도 모델에 따라 결과가 달라지고 일부 모델은 특정 샘플링 설정을 제한한다. CLI의 `0`~`1` 범위가 모든 모델의 지원을 보장하지는 않는다. 비교할 때는 제공자·모델·diff를 고정하고 한 번에 한 설정만 바꾼다. 한국어·필수 항목 지시와 검증은 별도로 유지한다.

### max_tokens와 결과 절단

`max_tokens`는 생성할 **출력 토큰의 최대치**이며 목표 분량이나 글자 수가 아니다. 한국어 글자 수와 토큰 수는 일치하지 않는다. 기본값 `2048`은 변경 요약과 본문, 이를 표현하는 JSON 구조를 모두 담는 예산이다. 응답이 먼저 끝나면 상한까지 채우지 않는다. 모델의 출력 한도와 입력 프롬프트를 포함한 컨텍스트 한도 안에서 설정해야 한다. [OpenRouter의 토큰 상한 설명](https://openrouter.ai/docs/api_reference/parameters#max-tokens)을 참고한다.

예산이 부족하면 문장이나 JSON이 완성되기 전에 응답이 끊겨 필수 항목이 누락되거나 형식 검증에 실패할 수 있다. 현재 CLI는 잘린 응답을 자동으로 이어 붙이지 않는다. 형식 오류는 모델의 지시 미준수로도 발생하므로 오류만 보고 토큰 부족으로 단정하지 않는다.

추론 모델은 제공자에 따라 내부 추론 토큰과 사용자에게 보이는 출력이 같은 상한을 공유한다. 충분한 본문이 나오지 않으면 추론 예산도 확인해야 한다. 현재 CLI에는 별도 추론 예산 옵션이 없으므로 모델의 제한을 확인한 뒤 출력 상한을 늘리거나 다른 모델을 선택한다. [OpenRouter의 추론 토큰과 출력 예산 설명](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens#reasoning-tokens-and-max_tokens)을 참고한다.

권장 조정 순서는 다음과 같다.

1. `--temperature 0.2 --max-tokens 2048`로 시작하고 본문 누락과 형식 오류를 확인한다.
2. 토큰 부족이 의심되면 다른 설정을 유지하고 모델 허용 범위에서 `3072`, `4096` 순으로 상한을 늘려 다시 실행한다.
3. 충분한 예산에서도 실패하면 모델의 한국어·JSON 지원과 변경 범위를 확인한다. 안전 모드가 생략한 입력은 출력 예산을 늘려도 복원되지 않으므로 변경을 작은 작업 단위로 나눈다.
4. 안정적으로 생성되면 작은 변경에서 `1024`처럼 낮은 상한도 검토할 수 있다. 필수 본문이 유지되는지 확인하고, 낮춘 값 때문에 재실행이 늘어나면 이전 값으로 돌아간다.

```sh
# 기본 설정
just pr --temperature 0.2 --max-tokens 2048

# 출력 예산만 늘려 다시 생성
just pr --temperature 0.2 --max-tokens 4096
```

상한을 올렸다고 항상 그만큼 생성하거나 과금되는 것은 아니지만, 더 긴 출력과 지연·비용 증가를 허용한다. 반대로 상한을 지나치게 낮춰 실패와 재실행이 늘면 총비용이 커질 수 있다. 위 명령은 각각 새 API 요청이며 자동 조정 기능은 아니다.

## LLM 제공자 변경

제공자와 모델 설정은 `CLI 옵션 > 셸 환경변수 > .env` 순서로 적용한다. 제공자를 생략하면 `openrouter`를 사용하지만, 모델은 모든 제공자에서 명시해야 한다.

| 제공자 | 기본 키 변수 | 추가 설정 |
| --- | --- | --- |
| `openrouter` | `OPENROUTER_API_KEY` | `--model` 또는 `LLM_MODEL`에 OpenRouter 모델 ID 지정 |
| `openai-compatible` | `LLM_API_KEY` | 모델과 API 주소 필수 (`--model`/`LLM_MODEL`, `--base-url`/`LLM_BASE_URL`) |
| `anthropic` | `ANTHROPIC_API_KEY` | `--model` 또는 `LLM_MODEL` 필수 |

```sh
# .env에 LLM_API_KEY를 먼저 설정한다.
just commit --provider openai-compatible --base-url https://your-provider.example/v1 --model YOUR_MODEL_ID

# .env에 ANTHROPIC_API_KEY를 먼저 설정한다.
just pr --provider anthropic --model YOUR_ANTHROPIC_MODEL_ID

# 다른 키 변수 이름을 사용하려면 이름만 전달한다.
just commit --api-key-env MY_OPENROUTER_KEY
```

`LLM_PROVIDER`, `LLM_MODEL`, `LLM_BASE_URL`, `LLM_API_KEY_ENV`로 같은 설정을 저장할 수 있다. 제공자를 바꿀 때 해당 제공자의 모델 ID와 키 변수를 지정한다. `LLM_BASE_URL`은 `openai-compatible`에서만 사용하므로 다른 제공자로 전환할 때 제거한다. 기본 OpenRouter 키를 다른 제공자에게 자동으로 전달하지 않는다.

제공자 선택과 인증값 조회는 별도 단계다. 먼저 `--provider` 또는 `LLM_PROVIDER`로 API 제공자를 선택하고, 그 제공자의 키를 읽는다. `ANTHROPIC_API_KEY`가 존재해도 Anthropic으로 자동 전환하지 않는다. OpenRouter 모델 ID의 `google/`도 모델 제작자를 나타낼 뿐 Google API로 연결을 바꾸지 않는다.

[Pydantic AI](https://pydantic.dev/docs/ai/models/overview/)는 제공자 접두사나 명시적인 Provider 객체로 연결을 선택하고, [Aider의 OpenRouter 연동](https://aider.chat/docs/llms/openrouter.html)은 `openrouter/` 모델 접두사와 `OPENROUTER_API_KEY`를 함께 사용한다. 이 프로젝트도 대문자 `OPENROUTER_API_KEY`를 사용하며 SDK에 명시적으로 전달한다.

키 변수 이름을 제공자와 독립적으로 관리하려면 다음처럼 지정한다. `LLM_API_KEY_ENV`의 값은 실제 키가 아닌 **키를 저장한 환경변수 이름**이다.

```dotenv
LLM_PROVIDER=openrouter
LLM_API_KEY_ENV=TEAM_LLM_TOKEN
TEAM_LLM_TOKEN=발급받은_API_키
```

호환 API는 HTTPS 주소를 사용한다. 로컬 서버는 `http://localhost:11434/v1`처럼 HTTP를 사용할 수 있으며, 인증이 없는 서버도 SDK 초기화를 위해 `LLM_API_KEY=local` 같은 빈 값이 아닌 값을 설정한다. 해당 모델이 지시를 따르고 JSON 형식의 한국어 응답을 생성할 수 있어야 한다.

제공자별 SDK 생성과 인증은 `gitdraft/providers.py`, 생성 프롬프트와 출력 검증은 별도 모듈에 있다. 새 프로토콜을 추가할 때는 설정의 제공자 목록·키 매핑과 `model_session`을 확장하고 나머지 생성 흐름을 재사용한다. [Pydantic AI 제공자 구조](https://pydantic.dev/docs/ai/models/overview/)와 [OpenRouter 연동](https://pydantic.dev/docs/ai/models/openrouter/)을 따른다.

## 출력 예시

다음은 인사 함수를 추가했을 때의 축약 예시다.

```text
--- Change Summary ---
- greeting.py에 이름을 받아 인사말을 반환하는 함수를 추가했다.

--- Commit Message ---
feat: 이름을 받는 인사 함수 추가

As-is
- 인사 함수가 없었다.

To-be
- 이름을 받아 한국어 인사말을 반환한다.

What
- greeting.py에 greet 함수를 추가했다.

Why
- 인사말 생성을 재사용하려는 변경으로 추정된다.

How
- 문자열 포매팅으로 인사말을 구성했다.
- 테스트 미실행: 초안 생성 과정에서 실행하지 않음.
- greet('철수')의 반환값을 수동으로 확인한다.
----------------------
```

커밋 제목은 `<영문 종류>: <한국어 요약>`이며 50자 이내를 권장하고 최대 72자로 후처리한다. 본문은 `As-is`, `To-be`, `What`, `Why`, `How`를 모두 포함한다.

```text
--- PR Title ---
이름을 받는 인사 함수 추가

--- PR Body ---
## Why
- 인사말 생성을 재사용하려는 변경으로 추정된다.

## What
- greeting.py에 greet 함수를 추가했다.

## How to Test
- 테스트 미실행: 초안 생성 과정에서 실행하지 않음.
- greet('철수')가 한국어 인사말을 반환하는지 확인한다.
----------------------
```

PR 제목은 최대 80자이며 세 본문 섹션에 각각 하나 이상의 불릿을 포함한다. 잘못된 구조나 한국어 설명 누락은 검증 오류로 종료하고, 긴 제목은 생략 부호로 줄인다. diff만으로 배경과 테스트 결과를 확정할 수 없으므로 생성된 문구와 제안된 테스트 명령을 검토한다.

## AI 초안의 편향과 오류

AI가 자연스럽고 확신에 찬 문장을 생성해도 사실이거나 중립적인 설명이라는 뜻은 아니다. 생성형 AI에는 사실을 지어내는 오류, 유해한 편향과 결과를 과신하는 자동화 편향이 있을 수 있다. [NIST 생성형 AI 위험 프로파일](https://nvlpubs.nist.gov/nistpubs/ai/NIST.AI.600-1.pdf)의 관련 설명을 참고한다. 이 도구의 자동 검증은 필수 항목, 한글 포함 여부, 제목 길이 등 형식을 확인하며 사실 정확성·중립성·완전성을 보장하지 않는다.

### 편향 가능성

이 프로젝트의 초안을 검토할 때는 다음과 같은 치우침을 확인한다.

- **관행·언어 편향**: 익숙한 기술이나 영어권 개발 관행을 기준으로 이 저장소의 의도와 다른 용어·설계 평가를 제시할 수 있다. 프로젝트 요구사항과 실제 코드에 맞춰 수정한다.
- **긍정적 효과의 과장**: 코드가 바뀌었다는 이유만으로 성능·보안·사용성이 개선됐다고 단정하거나 호환성 문제를 빠뜨릴 수 있다. 측정·검증 근거가 없는 효과는 삭제하거나 확인이 필요하다고 적는다.
- **사람에 대한 부당한 판단**: 작성자의 능력·의도나 특정 사용자 집단을 근거 없이 평가할 수 있다. 사람에 대한 비난과 고정관념을 제거하고 관찰 가능한 동작으로 설명한다.
- **입력 선택에 따른 편중**: 안전 모드의 파일·줄 제한과 민감 파일 제외 때문에 일부 변경만 강조될 수 있다. 포함된 diff만으로 전체 변경이나 PR 전체를 설명했다고 간주하지 않는다.

### 주요 오류 유형

| 오류 유형 | 초안에서 확인할 예 | 검토 기준 |
| --- | --- | --- |
| 사실 생성·잘못된 인과관계 | 없는 함수·이슈를 언급하거나 변경 이유를 확정함 | 파일·심벌·요구사항을 대조하고 확인되지 않은 이유는 삭제하거나 추정으로 표시한다. |
| 변경 방향·범위 오해 | 삭제를 추가로 설명하거나 스테이징 전후 변경을 중복 요약함 | 추가·삭제된 줄과 실제 적용할 파일 범위를 비교한다. |
| 누락·의미 손상 | 예외 처리·호환성 변경을 빠뜨리거나 짧아진 제목에서 부정 표현이 사라짐 | 핵심 동작과 영향이 남아 있는지 원본 diff와 비교한다. |
| 검증 결과 조작 | 실행하지 않은 테스트를 통과했다고 쓰거나 측정하지 않은 개선 수치를 제시함 | 직접 실행한 명령과 결과만 기록하고 미실행 항목은 이유를 명시한다. |
| 용어·형식 오류 | 한글은 포함하지만 번역이 부정확하거나 커밋 종류가 변경 목적과 다름 | 자연스러운 한국어와 저장소 규칙을 사람이 확인한다. |
| 민감정보·입력 지시 혼입 | 마스킹되지 않은 정보가 남거나 diff 속 주석의 지시가 초안에 반영됨 | 비밀 값·개인정보·내부 정보를 제거하고 저장소 내용은 요약할 데이터로만 취급한다. |

### 수동 검토 절차

커밋 메시지와 PR 설명에 적용하기 전에 아래 순서로 검토한다. 재생성한 결과도 같은 절차를 거친다.

1. **대상 변경을 확정한다.** `git status --short`, `git diff`, `git diff --cached`로 파일과 변경 내용을 확인하고, 일반 diff에 나오지 않는 새 파일은 직접 읽는다. 초안은 스테이징·미스테이징·새 파일을 함께 포함하므로 실제 커밋할 범위와 일치시킨다. PR은 대상 브랜치와의 전체 차이도 별도로 확인한다.
2. **각 주장에 근거를 연결한다.** 제목과 본문의 문장별로 파일·변경 줄·요구사항을 대조한다. `As-is`와 `To-be`의 방향, `What`의 누락, `Why`의 추정을 확인한다. 입력 제한 로그가 있으면 생략된 변경을 직접 검토하고 필요한 내용을 보완한다.
3. **검증 결과를 직접 확인한다.** 제안된 테스트 명령이 실제로 존재하고 변경에 적합한지 검토한 뒤 실행한다. 코드 변경에는 `just test -q`, 의존성에는 `just check` 등을 활용하고 실행 명령과 실제 결과를 `How` 또는 `How to Test`에 기록한다. 문서만 바꾼 경우에는 링크·예시 검토를 기록할 수 있다. 실행하지 않은 검증은 미실행 사실과 이유를 남긴다.
4. **편향과 민감정보를 제거한다.** 근거 없는 성능·보안 보장, 사람에 대한 평가, 특정 관행을 강요하는 표현을 구체적인 변경 설명으로 고친다. 마스킹이 모든 정보를 찾지는 못하므로 키·이메일·내부 주소 등 공개하면 안 되는 내용도 확인한다.
5. **최종 형식과 의미를 확인한다.** 커밋 제목은 `<영문 종류>: <한국어 요약>`과 최대 72자, 본문은 `As-is`, `To-be`, `What`, `Why`, `How`를 확인한다. PR은 제목 최대 80자와 `Why`, `What`, `How to Test`의 불릿을 확인한다. 길이를 줄이면서 의미가 바뀌지 않았는지도 다시 읽는다.
6. **확인한 문구만 적용한다.** 오류는 직접 수정하거나 원인을 조정해 재생성하고, 근거 없는 단정은 삭제하거나 확인이 필요한 추정으로 명시한다. 실제 커밋 직전에는 `git diff --cached`를 다시 확인한다. 화면의 구분선·상태 로그를 제외하고 메시지 내용만 복사한다. 검토 후 코드나 대상 파일이 바뀌었다면 관련 설명과 검증 결과도 갱신한다.

예를 들어 diff에서 중복 호출 제거만 확인했다면, `성능이 크게 향상됐고 모든 테스트를 통과했다`는 문구를 그대로 사용하지 않는다. 실제 상태에 맞춰 `중복 호출을 제거했다. 성능 측정은 미실행이며 테스트 결과는 별도 확인이 필요하다`로 수정하고, 이후 직접 확인한 결과를 반영한다.

## 재생성과 후처리 선택 기준

**재생성**은 입력이나 설정을 조정해 LLM에 다시 요청하는 것이고, **후처리**는 받은 응답에 로컬 규칙을 적용하는 것이다. 현재 구현은 `1회 생성 → 구조·한국어 항목 검증 및 정규화 → 민감정보 마스킹과 재검증 → 제목 길이 후처리·렌더링`을 수행한다. SDK와 Agent의 자동 재시도는 꺼져 있으므로 검증 실패 시 종료하며, 재생성이 필요하면 사용자가 명령을 다시 실행한다.

| 관점 | 후처리를 선택할 때 | 재생성을 선택할 때 |
| --- | --- | --- |
| 정확도 | 내용은 맞고 공백·줄바꿈·불릿 등 표현 형식만 고치면 될 때 적합하다. 누락된 사실이나 잘못된 변경 이유는 복원하지 못한다. | 핵심 변경을 빠뜨렸거나 의미를 잘못 해석해 새로운 요약이 필요할 때 적합하다. 재생성도 사실 정확성을 보장하지 않으므로 diff와 대조한다. |
| 제어성 | 제목 길이·섹션 헤더처럼 명확한 규칙을 일관되게 적용할 수 있다. 제목 절단은 의미를 훼손할 수 있어 검토가 필요하다. | 단순 절단으로 의미를 유지할 수 없거나 구조·한국어 요구를 충족하지 못했을 때 새 문장을 생성한다. 낮은 온도에서도 결과가 달라질 수 있다. |
| 효율성 | 추가 API 요청이 없어 비용과 지연이 작다. 현재 제목 길이 제한과 서식 통일에 사용한다. | 새 요청의 입력·출력 비용과 응답 대기 시간이 발생한다. 실패 원인에 맞게 설정이나 입력을 조정한 뒤 필요한 경우에만 다시 요청한다. |

이 프로젝트에서는 다음 기준으로 처리한다.

- **공백·줄바꿈·불릿 형식**: 정규화하고 검증된 필드로 섹션을 렌더링한다. 비어 있는 필수 본문을 임의 문장으로 채우지는 않는다.
- **긴 제목**: 커밋 72자, PR 80자 이내로 생략 부호를 붙여 줄인다. 이는 API의 토큰 예산 부족에 따른 응답 절단과 별개다. 핵심 동작이나 부정 표현이 잘렸다면 사람이 의미를 보존해 수정하거나 재생성한다.
- **잘린 JSON·필수 항목 누락·한국어 설명 부족**: 검증 오류로 종료한다. 토큰 예산이나 모델을 확인하고 다시 요청하며, 누락된 의미를 추측해 후처리하지 않는다.
- **사실 오류·근거 없는 테스트 성공 주장**: 형식 검증만으로 탐지할 수 없다. 사용자가 diff와 실제 검증 결과를 대조해 수정한다. 재생성만으로 확인되지 않은 사실을 확정하지 않는다.

Pydantic AI는 검증 피드백을 통한 재시도를 지원하지만, 이 프로젝트는 비용과 호출 횟수를 제어하기 위해 `retries=0`, `request_limit=1`을 사용한다. 사용자가 재실행하는 경우에도 이전 실패 응답이 자동으로 전달되지는 않는다. [Pydantic AI 출력 검증 문서](https://pydantic.dev/docs/ai/core-concepts/output/#output-validators)를 참고한다.

## 안전 모드와 비용

기본 안전 모드는 최대 **10개 파일, diff 200줄, 40,000자**만 전송한다. 잘린 입력은 로그와 프롬프트에 표시한다. 전송 순서는 Git 상태와 패치 순서를 따르므로 큰 변경에서는 일부 파일의 내용이 빠질 수 있다.

`.env`, `.env.*`, 개인 키 파일 등은 항상 제외하며, 알려진 환경변수의 키, 기본 토큰 패턴과 이메일은 마스킹한다. 새 심볼릭 링크는 외부 파일을 읽지 않도록 제외한다. `--no-safe-mode`는 전송량 제한만 해제한다. 패턴 기반 마스킹이 모든 개인정보나 비밀을 찾는 것은 아니므로 실행 전 변경 내용을 검토한다.

명령당 LLM 요청은 최대 **1회**다. SDK와 Agent의 자동 재시도는 꺼져 있고 호출 시도 횟수를 로그로 남긴다. 실패한 요청도 과금될 수 있으며 다시 실행하면 새 요청이다. 모델과 입력량에 따라 비용이 달라진다. 이 프로그램은 커밋, push, 원격 PR 생성을 실행하지 않는다.

## 오류 대응

- 모델 누락: `--model` 또는 `.env`·셸 환경변수의 `LLM_MODEL`에 빈 값이 아닌 모델 ID를 지정한다.
- 키 누락: 선택한 제공자의 키 변수와 `.env` 위치를 확인한다.
- HTTP 401·403: 키의 유효성과 API 접근 권한을 확인한다.
- HTTP 402·429: 잔액이나 요청 한도를 확인한다.
- 연결 실패·시간 초과: 네트워크, API 주소와 제공자 상태를 확인한다. 필요한 경우 `--api-timeout` 또는 `--git-timeout`을 조정한다.
- 응답 형식 오류: 모델의 한국어·JSON 출력 지원을 확인한다. 토큰 부족이 의심되면 [생성 파라미터 조정](#생성-파라미터-조정)에 따라 출력 예산을 늘린다.

키, API 오류 응답 본문과 원본 diff는 오류 로그에 출력하지 않는다.

## 개발과 검증

```sh
just test                 # 실제 LLM 호출 없이 전체 pytest 실행
just test -q              # 간단한 테스트 결과
```
